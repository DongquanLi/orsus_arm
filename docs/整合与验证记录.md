# .148 / .149 工程整合记录

基线 Git 提交：`cc88071a69db17937d9e64f69ccc2a6dfcb49fd2`。2026-10-30 对比两台设备和本地工作区，核心 SDK、录制/回放和相机源码一致；`.149` 补齐了 glog、NLopt 等新系统依赖并安装 GPIO 自启动。当前整合保留全部功能修改，不复制录制数据、机器日志、安装回执或编译缓存到 Git。

## 合并的行为

- 将 GPIO142/118 初始化脚本和 systemd 服务收进仓库，开机在 CAN 之前运行，每次开机最多一次复位。
- 新设备安装入口统一安装依赖、USB 自启、SLCAN、CAN 服务、编译与自检。
- 自动发现当前 CANable 序列号；不再绑定一块特定 CAN 板，也不假设必须为 ttyACM0。
- USB 快照、拓扑、拔插比较和有限时间取流测试，日志按次保留。
- 回零、重力补偿、录制在同一驱动内衔接；自动裁剪前导等待，保留 raw 原件。
- 默认 normal 回放与约 3 秒起步等待；新增自动管理 control 驱动的一键回放。
- README 统一说明正常档为 0.5× 时间轴；旧低层发布脚本仍需要单独 control。

## 已有真实设备证据（整合前）

| 设备 | 相机 | 禁用状态机械臂通信 |
|---|---|---|
| .148 | 20 秒 502 帧，约 25 Hz | 45 秒 8997 条 ROS2 反馈，约 199.90 Hz；ENOBUFS 0 |
| .149 | 20 秒 502 帧，接收约 25.01 Hz | 30 秒 6002 条 ROS2 反馈，约 200.01 Hz；ENOBUFS 0 |

以上为测试当时相机位于 USB3-1、CANable 位于 USB4-1.2 的结果，不能推出所有端口或任意接线长期稳定。`.70` 曾在 GPIO 初始化后仍枚举失败。SDK 未启动时的 CAN RX=0 不能单独判断硬件失败。

## 测试范围

离线轨迹、裁剪与原件保护、CAN 进程所有权测试，以及隔离 DDS 的录制流程模拟由 deploy/test_*.py 提供。真实禁用通信测试不会发送运动目标。自动回零、切换重力补偿以及新的一键回放完整运动，需在现场继续验收；本次工程整合不以机器人运动作为自动测试。

USB/CAN 自启应在下次整机重启后，检查服务、设备枚举和取流再次确认。当前服务执行成功与 enabled 不等同于已完成重启验收。
